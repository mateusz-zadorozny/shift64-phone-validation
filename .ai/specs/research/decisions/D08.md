# D08 — Rename to "SHIFT64 Phone Validation for WooCommerce", slug and text domain `shift64-phone-validation`

- Date, owner: 2026-10-12, Mateusz Zadorożny (maintainer)
- Context and the options weighed: the WordPress.org pre-review of the 2.0.0 submission (Review ID `AUTOPREREVIEW ❗TRM-OWN verify-phone-number-shift64/mateuszz/10Oct26`, received 2026-10-10) found the name "Verify Phone Number Shift64" not distinctive enough: it starts with the generic phrase "Verify Phone Number" and puts the distinctive term at the end, while the directory expects the name to be distinguishable from other phone-validation plugins from its beginning. The review also asked for proof that the submitting account owns the SHIFT64 brand, because the account email is on gmail.com. A submission that leaves a reported issue unaddressed is rejected, so keeping the name (D06) was no longer an option. Options weighed for the slug: `shift64-phone-validation` (short, no third-party trademark in the slug), `shift64-phone-validation-for-woocommerce` (keywords in the URL, a 40-character text domain), and the review AI's `shift64-phone-validation-woocommerce` (no "for", which the review's own naming examples require). All three were free in the directory on 2026-10-12, and no plugin there contains "shift64". Options weighed for the version: a major release, because `BACKWARD_COMPATIBILITY.md` §6 calls a text domain change breaking, or a patch, because the plugin is not in the directory yet and both known installs are the maintainer's own.
- Decision and why: the display name is "SHIFT64 Phone Validation for WooCommerce" and the slug, the text domain, the main plugin file, the release ZIP and the GitHub repository are `shift64-phone-validation`. The distinctive term comes first, and WooCommerce follows "for", the pattern the review names for a trademark the author does not own. Ownership of SHIFT64 is shown with the DNS TXT record `wordpressorg-mateuszz-verification` on shift64.com, set by the maintainer on 2026-10-12. The change ships as a patch release (2.0.1), not a major: the text domain changes before any directory install exists, so no third-party translation exists to invalidate, and `BACKWARD_COMPATIBILITY.md` §6 records this one exception. The agent recommended the short slug, the TXT record, renaming the repository and a major release; the maintainer chose all of them except the major release.
- Consequences, and what would make us revisit it: an install from before 2.0.1 (folder `verify-phone-number-shift64` or `verify-phone-number-shift64-master`) is a different plugin to WordPress and is replaced once with WP-CLI, which keeps the settings (README, *Moving an existing install to WordPress.org updates*); the options, filters, order meta and the PHP namespace keep their names. The 1.4.x GitHub updater looks for `verify-phone-number-shift64.zip`, which releases from 2.0.1 on do not carry, so it offers nothing newer than 2.0.0. The review must be asked, in the same thread, to change the slug to `shift64-phone-validation`; the slug cannot change after approval. The listing text keeps the statement D06 required (the plugin validates numbers, sends no SMS or one-time codes, and does not confirm that a number belongs to the customer), so N01 and the closing of Q03 are unchanged. Revisit only if the review team rejects the name or the slug.
