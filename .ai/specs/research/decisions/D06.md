# D06 — Keep the name "Verify Phone Number Shift64"; the directory listing says the plugin validates numbers and confirms nothing

- Date, owner: 2026-10-06, Mateusz Zadorożny (maintainer)
- Context and the options weighed: N01 records that the plugin will never confirm that a number belongs to the customer, and that the name "Verify Phone Number" invites that expectation in the WordPress.org directory; Q03 asked whether the name creates that expectation and whether the listing text should address it. Submitting to the directory (issue #31) forced the naming question. WordPress.org derives the plugin's slug from the `Plugin Name` header at submission ("your slug will be boaty-mcboatface" for "Plugin Name: Boaty McBoatface", https://wordpress.org/plugins/developers/add/), and the review team expects the text domain to equal the slug ("the translation domain needs to be the same as your plugin slug", https://developer.wordpress.org/plugins/wordpress-org/common-issues/). This plugin's slug must therefore stay `verify-phone-number-shift64`, the text domain that `BACKWARD_COMPATIBILITY.md` §6 protects, because changing it invalidates every existing translation. Two options were weighed: keep the name and state in the listing what the plugin does and does not do; or submit under a different display name and ask the review team, at review, for the `verify-phone-number-shift64` slug, at the risk that the granted slug differs from the text domain.
- Decision and why: keep the name "Verify Phone Number Shift64". The directory listing (`readme.txt`) states that the plugin validates numbers, and that it does not send SMS or one-time codes and does not confirm that a number belongs to the customer. Renaming would trade an ambiguity that the listing text can correct for a slug that might not match the protected text domain. The agent recommended keeping the name; the maintainer accepted that recommendation on 2026-10-06. Whether the name actually creates the expectation (Q03) was not measured; this decision closes Q03 by addressing it in the listing text, not by evidence about users.
- Consequences, and what would make us revisit it: the slug, the text domain and the main plugin file name stay `verify-phone-number-shift64`. The listing text carries the "validates, does not confirm" statement, so a listing change that drops it contradicts this entry. N01 is unchanged. Revisit if directory reviews or support requests show users expecting SMS or code confirmation.
